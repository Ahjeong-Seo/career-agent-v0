# 용어집

이 문서는 v0 규칙 기반 채점 설계에서 팀이 같은 의미로 사용할 용어를 정리한다. schema version 2의 checklist·score 구조는 공식 파일과 v0 사본에 동일하게 반영되어 있다.

| 용어 | 정의 |
| --- | --- |
| 케이스 (`case`) | 채용공고 하나와 사용자 한 명의 조합. 파일 간 `case_id`로 연결한다. |
| 체크리스트 항목 (`item`) | 채용공고에서 확인할 요건 하나. checklist의 `items[].id`와 다른 파일의 `item_id`로 연결한다. |
| 채점 대상 항목 | 확정 체크리스트 중 규칙 기반 상태 판정을 수행하는 항목. v0에서는 모든 확정 항목을 대상으로 본다. |
| 경험 응답 준비 | 각 채점 대상 항목에 사용자가 경험 원문을 입력했거나, `경험 없음`을 명시적으로 선택한 상태. 빈칸은 준비된 응답이 아니다. |
| 미작성 | 경험 응답이 아직 제출되지 않은 상태. `경험 없음`과 다르며 채점을 시작할 수 없다. |
| 경험 있음 | 사용자가 해당 체크리스트 항목에 대한 경험 원문을 입력한 상태. 원문은 수정하거나 다듬지 않고 보존한다. |
| 경험 없음 | 사용자가 해당 항목에 관련 경험이 없다고 명시적으로 선택한 상태. 내용을 생성해 채우지 않는다. |
| experience payload | `schema_version`, `case_id`, `experiences`를 포함한다. `experiences[]`에는 경험 있는 항목의 `{item_id, text}`만 두고, 생략된 항목은 프론트가 모든 선택을 확인한 뒤 경험 없음으로 처리한다. |
| 충족 | 경험 근거가 있고, 결과 문안에서 체크리스트 키워드 중 하나 이상이 확인된 상태. |
| 미충족 | 경험은 있지만 결과 문안에 요건 키워드가 없거나 문안이 요건을 반영하지 않은 상태. |
| 품질 경고 (`issue`) | 문안의 요건 상태와 별도로 확인하는 원문에 없는 숫자 또는 등록된 정형 표현. v0에서 경고 데이터는 한 `issues` 목록에 저장한다. |
| attempt | 동일한 입력 스냅샷을 기준으로 수행하는 한 번의 작업 묶음. 그 안에서 생성한 세 스타일 결과는 같은 attempt를 공유한다. |
| style | 문안 생성 방식. `성과 강조형`/`achievement`, `키워드 맞춤형`/`keyword`, `간결형`/`concise`를 뜻한다. |
| 점수 (`score`) | 체크리스트 항목 상태·근거·품질 경고와 항목별 점수를 담는 결과 레코드. 합격 예측이나 총점을 뜻하지 않는다. |
| 재검토 필요 | 결과 문안에 수정·확인이 필요한 항목 또는 품질 경고가 있음을 알리는 표시. 합격/불합격 판정이 아니다. |
| 공식 계약 | 팀이 합의해 `schemas/`와 `samples/`의 정식 파일에 반영한 데이터 형식. 현재 checklist·score는 schema version 2를 사용한다. |
