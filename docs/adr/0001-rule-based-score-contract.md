# ADR 0001: v0 규칙 기반 채점 결과 계약

- 상태: 적용
- 날짜: 2026-10-28
- 맥락: 이번 주 프로젝트 진행 목표 및 사용자의 점수 정책 결정

## 결정

1. 결과는 합격 예측이 아니라 체크리스트 반영 상태와 재검토 이유를 보여준다. `passed` 필드는 사용하지 않는다.
2. 상태 허용값은 `충족`, `미충족`, `경험 없음`이다. 빈 응답은 미작성으로 두고, 경험 없음은 사용자가 선택한다. 모든 항목의 경험 응답이 준비되어야 채점을 시작한다.
3. 키워드 하나 이상이 rewrite 문장에 포함되면 충족이다.
4. 첫 attempt에서 성과 강조형·키워드 맞춤형·간결형 rewrite를 각각 만든다. 각 rewrite는 별도 `score_case` 호출과 score 레코드에 대응하며 세 결과가 같은 `attempt_id`와 번호를 공유한다. 이후 재작업은 선택한 한 스타일로 진행한다.
5. 필수 항목은 최대 10점, 우대 항목은 최대 5점이다. 충족이면 만점, 그 외 상태는 0점이다. 총점은 내지 않는다.
6. 수치 근거 유무는 check로 표시하되 점수에 반영하지 않는다. 원문에 없는 숫자·정형 표현·경험이 없는데 생성된 문장은 항목을 참조하는 `issues`에만 저장하고 감점하지 않는다.
7. 입력을 바꾸어 재작업하면 새 attempt를 만들고 과거 결과를 보존한다. 최대 attempt 횟수는 고정하지 않는다.
8. score의 `items`는 확정 checklist의 채점 대상 항목만 담는다. 현재 v0에서는 모든 확정 항목이 채점 대상이다.
9. 공식 및 v0 score/checklist schemas와 samples는 같은 필드 구조와 점수 규칙을 사용한다. score 계약은 schema version 2다.

## 결과

첫 attempt의 세 rewrite 파일을 각각 채점하고 스타일별 상태·이유·항목 점수·경고를 표시한다. 다음 rewrite용 feedback도 결과별로 제공한다. 현재 화면의 attempt 이력은 Streamlit 세션에 보존된다.

## 검토한 대안

- 총점 및 합격 게이트: 채용 결과 예측으로 오해될 수 있어 사용하지 않는다.
- 품질 경고 감점: 키워드·상태 점수와 별개로 사람이 검토하도록 표시만 한다.
- 세 스타일을 한 rewrite/score 객체로 합치기: case·style·attempt 식별을 유지하기 위해 스타일별 레코드를 사용한다.
