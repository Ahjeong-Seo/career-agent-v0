# 채점 결과 데이터 약속

[1차 회의록](https://app.notion.com/p/1-3ed393663bcd80e6aff9d97c8850000e)의 2.3·3.4 합의에 따라 `schemas/score.json`을 작성했다. 이 문서와 스키마는 채점 결과를 주고받는 형식을 정하며, 실제 채점 코드를 구현하지 않는다.

평가팀은 첨삭할 때마다 결과 한 개를 만들어 루프팀과 프론트팀에 전달한다. 현재 샘플 버전은 `schema_version: 1`이다. 기존 샘플의 내용은 유지하고 `schema_version`과 `style_id: "achievement"`를 추가했다.

## 반드시 포함하는 값

- `schema_version`: 1 이상의 정수. 스키마 변경을 PR로 병합할 때 버전을 관리한다.
- `case_id`: 처리한 사례의 ID 문자열.
- `attempt`: 1~4 정수. 첫 생성은 1, 이후 최대 세 번 다시 쓴 결과는 2~4이다.
- `style_id`: `achievement`, `keyword`, `concise` 중 하나.
- `passed`: 통과 여부를 나타내는 불리언.
- `items`: 체크리스트의 모든 항목을 각각 한 번씩 담는 배열. 각 항목은 `item_id`, `status`, `reason`을 포함한다. 상태는 `충족`, `미충족`, `경험 없음` 중 하나다.
- `made_up_numbers`: 원래 경험에 없는 숫자 목록. 각 항목의 `item_id`, `number`, `reason`은 문자열이다. `number`는 기존 샘플처럼 `"3"`으로 전달한다.
- `ai_phrases`: 검출한 AI 표현 목록. 각 항목은 문자열 `item_id`, `phrase`를 포함한다.
- `feedback`: 문자열. 통과한 결과에서는 정확히 빈 문자열 `""`이어야 한다.

`made_up_numbers`와 `ai_phrases`는 발견한 문제가 없어도 키를 생략하지 않고 `[]`를 보낸다. 숫자 총점이나 `points` 필드는 합의되지 않아 정의하지 않았다.

## 스키마 검사와 별도 코드 검사의 경계

JSON Schema Draft 2020-12 검증은 필수 키, 자료형, 허용 상태·스타일, 회차 범위, 통과 시 빈 피드백을 검사한다. 이 결과는 LLM의 출력 스키마가 아니므로 최상위와 중첩 객체 모두 `additionalProperties: true`를 사용한다. 소비 코드는 모르는 키를 무시해야 하며, JSON Schema가 그 키를 삭제해 주는 것은 아니다.

아래 내용은 다른 파일이나 채점 규칙과 대조해야 하므로 별도의 코드 검사에 속한다. 이번 작업에서는 그 검사기와 채점 로직을 구현하지 않는다.

1. `items[].item_id`가 중복되지 않고, 체크리스트의 전 항목이 누락이나 추가 없이 정확히 한 번씩 있는지 확인한다. 객체 전체의 중복 검사만으로는 같은 ID와 다른 설명을 가진 항목을 잡을 수 없다.
2. 오류 목록의 `item_id`가 유효한 체크리스트 항목을 참조하는지 확인한다. 같은 항목에 서로 다른 숫자나 표현이 여러 개 검출될 수 있으므로 오류 목록의 ID가 반복된다는 이유만으로 거부하지 않는다.
3. `case_id + style_id + attempt`가 해당 첨삭 결과 및 현재 실행과 일치하는지 확인한다. 다른 스타일·회차의 결과를 현재 화면에 섞지 않는다.
4. 경험을 입력한 필수 항목이 모두 충족되고, 지어낸 숫자와 AI 표현이 없을 때만 `passed`가 참인지 확인한다. 우대 항목은 표시하고 경험이 없는 항목은 `경험 없음`으로 표시한다. 점수나 경험을 임의로 만들어 채우지 않는다.

## 확인 방법
