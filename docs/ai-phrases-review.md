# 이력서 표현 검토 메모

2026-10-17 · 프론트팀 공유용

표현만으로 AI 작성 여부를 단정할 수 없다. 이 목록은 행동·대상·근거가 빠진 문장을 찾아 구체성을 점검하는 휴리스틱이다. 아래 예시는 모두 가상이며, 개인 이력서에서 가져오지 않았다.

## 현재 탐지 목록: 등록된 3개

`scoring/ai_phrases.txt`에 등록된 표현은 다음과 같다.

- 적극적으로 기여
- 역량을 강화
- 다양한 경험을 통해

이 메모는 자동 탐지 목록과 코드를 수정하지 않는다. 저장소의 합의대로 **등록 표현과 정확히 일치하는 경우를 탐지 대상으로 삼고, 체크리스트 `keywords`에 있는 단어는 예외로 둔다.** 유사어·활용형을 자동으로 포함하거나 아래 후보를 즉시 감점 대상으로 삼지 않는다.

## 추가 검토 후보: 10개

평가팀과 검토할 후보이며, 현재 탐지 목록에는 포함되지 않는다. 문맥상 충분한 설명이 있는 표현까지 일괄 배제하지 않는다. 각 개선 예시는 방향을 보여 주는 가상 문장이다. 실제 수정에는 원래 경험 글에서 확인되는 사실만 사용하고, 사실이 없으면 질문으로 남긴다.

### 1. 주도적인 역할을 수행

문제: 본인이 결정하거나 실행한 일이 드러나지 않는다.

원문: “프로젝트에서 주도적인 역할을 수행했습니다.”

개선: “기능별 작업 순서를 정리하고, 팀 회의에서 담당자와 완료 기준을 합의했습니다.”

구체화: 직접 맡은 결정과 산출물을 확인한다.

### 2. 원활한 커뮤니케이션

문제: 누구와 어떤 의견 차이를 어떻게 조율했는지 알 수 없다.

원문: “원활한 커뮤니케이션으로 협업했습니다.”

개선: “기획자와 개발자의 입력 항목 해석 차이를 정리하고, 화면 예시를 공유해 필수 항목을 합의했습니다.”

구체화: 협업 상대, 쟁점, 합의 방법을 확인한다.

### 3. 뛰어난 문제 해결 능력

문제: 능력에 대한 평가만 있고 문제와 해결 행동이 없다.

원문: “뛰어난 문제 해결 능력을 발휘했습니다.”

개선: “빈 입력에서 발생한 오류를 재현하고, 입력 검증과 오류 안내를 추가했습니다.”

구체화: 문제의 조건, 원인 확인 과정, 수정 내용을 확인한다.

### 4. 사용자 중심의 사고

문제: 어떤 사용자 의견이나 행동을 반영했는지 빠져 있다.

원문: “사용자 중심의 사고로 화면을 개선했습니다.”

개선: “테스트 참여자가 필수 입력을 놓치는 모습을 확인하고, 입력란 옆에 필수 표시와 예시를 추가했습니다.”

구체화: 관찰한 불편과 그에 대응한 화면 변경을 확인한다.

### 5. 업무 효율성을 향상

문제: 줄이거나 바꾼 업무가 무엇인지 알 수 없다.

원문: “업무 효율성을 향상했습니다.”

개선: “반복해서 복사하던 보고서 항목을 템플릿으로 만들고, 작성 절차를 문서화했습니다.”

구체화: 기존 절차와 바뀐 절차를 확인한다. 측정하지 않은 시간 절감률은 넣지 않는다.

### 6. 시너지를 창출

문제: 협업의 방식과 결과가 추상적이다.

원문: “팀원들과 시너지를 창출했습니다.”

개선: “백엔드 담당자와 응답 필드를 합의하고, 같은 샘플 데이터로 화면과 API 연결을 점검했습니다.”

구체화: 각자의 역할과 함께 만든 결과물을 확인한다.

### 7. 끊임없는 학습

문제: 배운 내용과 실제 적용 근거가 없다.

원문: “끊임없는 학습으로 성장했습니다.”

개선: “Streamlit의 입력 위젯 사용법을 익히고, 체크리스트 항목을 수정하는 화면에 적용했습니다.”

구체화: 학습 주제와 적용한 작업을 확인한다.

### 8. 혁신적인 솔루션

문제: 새롭다는 평가를 뒷받침하는 변경 내용이 없다.

원문: “혁신적인 솔루션을 제안했습니다.”

개선: “메일로 모으던 요청을 입력 폼으로 받도록 제안하고, 필수 항목을 포함한 시제품을 만들었습니다.”

구체화: 기존 방식의 불편, 제안 내용, 실제 수행 범위를 확인한다.

### 9. 성공적으로 완수

문제: 완료한 범위와 확인 기준이 빠져 있다.

원문: “프로젝트를 성공적으로 완수했습니다.”

개선: “입력 화면과 결과 화면을 구현하고, 팀이 정한 샘플 시나리오로 시연을 마쳤습니다.”

구체화: 담당 범위와 완료를 확인한 방법을 확인한다. 시연과 실제 배포를 구분한다.

### 10. 비즈니스 가치를 창출

문제: 어떤 대상에게 어떤 도움이 있었는지 설명하지 않는다.

원문: “서비스 개선으로 비즈니스 가치를 창출했습니다.”

개선: “상담 담당자가 문의 유형을 확인할 수 있도록 유형별 목록과 필터를 만들었습니다.”

구체화: 도움을 받은 대상과 가능해진 일을 확인한다. 매출·전환율 성과는 확인된 근거가 있을 때만 쓴다.

## 팀 검토 때 확인할 것

- 후보별로 구체적인 설명이 함께 있어도 불필요하게 걸리는지 확인한다.
- 체크리스트 `keywords` 예외와 정확히 일치하는 표현의 탐지 기준을 유지한다.
- 채택할 표현과 예외 적용 사례를 평가팀과 합의한 뒤 별도 변경으로 반영한다.
- 원래 경험 글에 없는 행동·결과·숫자를 보태지 않는다. 수치가 없으면 관찰 가능한 변경이나 산출물로 설명한다.
