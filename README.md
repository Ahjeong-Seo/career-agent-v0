# career-agent-v0

채용공고와 경험을 바탕으로 이력서 문장을 첨삭하고 코드로 채점하는 팀 프로젝트입니다.

## 현재 실행할 수 있는 화면

채용공고와 회사정보를 입력해 `jd.txt`로 준비하고, 샘플 체크리스트를 수정·확정한 뒤 항목별 경험을 입력할 수 있습니다. 첫 채점에는 세 스타일 rewrite를 각각 올려야 하며, rewrite마다 원문과 첨삭문, 항목별 점수·상태·경고를 확인할 수 있습니다. 입력을 바꾼 재작업에는 선택한 한 스타일 rewrite를 올립니다.

공고 파싱과 LLM 첨삭 생성은 아직 연결되지 않았습니다. 결과 화면은 loop에서 받은 rewrite JSON을 입력으로 받습니다. 채점은 `scoring.score.score_case`에서 규칙으로 수행합니다. 공식 및 v0 score/checklist 스키마와 샘플은 같은 schema version 2 계약을 사용합니다. 경험 입력은 공식 experience payload 모양으로 채점기에 전달되며 입력·시도 이력은 현재 세션 안에만 유지되고 파일로 자동 저장하거나 다운로드하지 않습니다. 표시되는 체크리스트는 입력한 공고를 분석한 결과가 아니라 `samples/checklist.sample.json`입니다.

## 시작하기

Python 3.11 이상에서 저장소 루트 기준으로 실행합니다.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
streamlit run app/main.py
```

키워드 목록 편집을 위해 Streamlit 1.66 이상을 사용합니다. 이 화면 실행에는 API 키나 LLM 호출이 필요하지 않습니다.

## 확인하기

```sh
.venv/bin/python -m unittest discover -s tests -v
```

입력 원문 보존, 체크리스트 편집·확정, 채점 규칙과 JSON Schema, Streamlit 화면 흐름을 검사합니다.

## 데이터 약속과 검토 자료

- [채점 결과 계약](docs/score-contract.md): 스타일별 rewrite마다 score 하나를 만들고 필수 10점·우대 5점 기준으로 항목을 채점하는 schema version 2를 설명합니다.
- [AI 표현 검토 후보](docs/ai-phrases-review.md): 기존 표현과 추가 후보 10개를 구분했습니다. 후보는 검토 자료이며 채점 목록에 자동 반영하지 않았습니다.
- [v0 채점 계약 ADR](docs/adr/0001-rule-based-score-contract.md): 상태와 품질 경고 분리, 스타일별 결과와 attempt 관계, 항목별 점수 결정을 기록합니다. 공식 스키마 변경은 팀 합의 후 반영합니다.
- [용어집](docs/glossary.md): 미작성·경험 없음, 채점 상태, issue, attempt 등 v0 설계 용어를 정리합니다.
- [규칙 기반 채점 v0 사양](docs/specs/rule-based-scoring-v0.md): 첫 attempt의 세 rewrite/score 연결, 이후 단일 스타일 재작업, 계약 및 검증 기준을 정리합니다.
- 체크리스트 편집은 기존 필드와 메타데이터를 보존하며 ID·유형·필수/우대 구분·항목 수는 바꾸지 않습니다. 파싱팀 스키마 병합 후 필수 메타데이터와 연결을 맞춰야 합니다.

## 이번 주 진행안 검토 (v0 초안)

- 입력 단계에서는 채용공고와 선택적 회사정보만 받습니다. 회사정보는 사업내용·인재상 중심이며 재무·SWOT·경쟁사·최근 이슈는 입력 안내에서 제외합니다. 이력서 입력과 자동 채움은 v1 후보입니다.
- 체크리스트는 사용자가 요구사항과 키워드를 확인하고 수정할 수 있게 합니다. 경험 입력의 빈칸(미작성)과 사용자가 명시한 `경험 없음`은 구분해야 합니다.
- score는 합격 예측이 아니라 문안의 요건 반영을 규칙으로 확인하는 결과입니다. 필수 항목은 최대 10점, 우대 항목은 최대 5점이며 충족이면 만점, 그 외에는 0점입니다. 수치 근거 유무는 표시만 하고 감점하지 않습니다.
- 스타일별 결과는 한 attempt로 묶고, 입력을 바꾸어 다시 채점하면 새 attempt로 기록합니다. 과거 결과는 현재 Streamlit 세션이 유지되는 동안 보존됩니다.
- 상세 검토와 팀 합의가 필요한 항목은 [주간 목표 및 v0 계약 검토](docs/v0-review.md)에 정리했습니다.

공식 및 `*.v0.*` 스키마·샘플은 같은 필드 구조와 점수 정책을 사용합니다. 점수 schema version 2는 항목 점수를 담으며 총점·감점 필드는 두지 않습니다. 화면의 시도 이력은 현재 세션에만 보존되며 영구 저장은 지원하지 않습니다.

실제 이력서, 로그인 정보, API 키, 캐시는 커밋하지 않습니다. 팀 간 데이터와 역할 규칙은 [AGENTS.md](AGENTS.md)를 따릅니다.
